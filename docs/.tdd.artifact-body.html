BrioCare · Technical Design Document

A deterministic brain with a narrow mouth

How the BrioCare prototype works: an event-sourced control loop where models transcribe and speak but never decide. Every technology choice below names the alternatives weighed and the trade-off accepted.

v0.1 · 29 August 2026 Author · Milton Ren Status · build-challenge submission Companions · PRD + field research

01 · The system at a glance

Senses, brain, mouth — and a human gate in front of the mouth

One Node agent process per session joins the LiveKit room as Brio. It transcribes every child's track separately, normalizes everything into one typed event stream, runs a deterministic facilitation engine over it, and speaks only through a validated expression layer — after the therapist has seen the intent. Convex holds durable state and live-syncs every UI.

The consequential judgment: no model in the control loop, and no speech-to-speech model in the room. The only model that hears audio is transcribe-only STT; the only model that produces audio reads one validated sentence at a time. Deciding when to act is deterministic TypeScript. The strongest case for the rejected option — an OpenAI Realtime speech-to-speech agent — is real: expressive duplex voice, natural repair ("oops — go ahead!"), less code. We rejected it because a group facilitator is silent most of the time, must be commandable by an external policy, needs per-child attribution a mixed conversation loses, and has to be testable without audio. Realtime returns where it fits: breakout-room conversations, Phase 2.

Trade-off: template fallbacks read plainer; that is the acceptable failure direction for a children's clinical setting.

03 · Real-time flow

One draw-out, end to end

The walk below is the core loop the interview will trace. Latency targets are stated per hop; the announce window dominates by design — it is consent, not lag. Ambient actions (pet energy, captions, stick visuals) skip the window and land in under ~150 ms.

  1. Sense. Maya has 0:12 of speech and one tap in 14 minutes; her ledger deficit crosses threshold. The trigger is audio-level accounting — it works even if STT is degraded.
  2. Propose. The engine's draw-out rule fires at the lowest untried ladder level and emits draw_out(maya, L0_group_cue) — class B, cooldowns checked, quiet-setting checked, therapist mode checked.
  3. Announce. The intent card renders on the panel via LiveKit data message (~50–100 ms): "Draw out Maya · quietest 14 min · group cue." A 4 s veto window opens. Block ends it; fire-now skips the wait; cue would have skipped it entirely.
  4. Validate. Window lapses. The expression layer fills the L0 template, optionally asks the LLM for one bounded variant, and runs the validator chain — length, sentence form, lexicon, no cross-child content. Any failure falls back to the raw template (~300 ms budget).
  5. Speak. Streaming TTS starts in ~300–500 ms; Brio's track plays "Let's hear from a few voices we haven't heard yet — thumbs up or thumbs down: did anyone else have a busy week?" Captions mirror it; the intent is marked fired with its full trace.
  6. Close the loop. Maya taps thumbs-up. The act lands in her ledger, her pet perks up, her deficit shrinks, and the L1 escalation that would have followed is cancelled. Total trigger-to-audio: ~5 s, ~4 s of which is the therapist's window.

Therapist commands ride the same data channel with pre-emptive priority: mute, hold, and block are applied in the agent before any queued TTS is flushed — a muted Brio cannot finish a sentence it already started rendering, because audio frames are gated at publish time, not at request time.

04 · The facilitation engine

A rule table, an intent lifecycle, and three action classes

Pure TypeScript, no I/O, no model calls. State: the exercise config (rounds, per-turn budget), turn state (stick holder, queue), a per-child ledger (airtime, acts, last contribution, prompts received, baseline multiplier from session setup), and mode flags (muted, held, autonomy dial). Every event or 1 s tick re-evaluates the rules; every decision logs event → rule → intent and is replayable from the event log alone.

Class A · ambient

Reversible, non-verbal, instant: pet states, captions, spotlights, timers, flags. No window. Suppressed by mute.

Class B · voiced

Anything Brio says aloud. Announce card + 4 s veto window (therapist can block, fire now, or let it lapse). *Cue-initiated speech skips the window — the tap is consent.

Class C · content-referencing

Anything quoting or targeting a child's own words, and L2 named invites. Explicit tap required — a lapsed timer is not consent here.

Intent lifecycle: proposed → announced → fired | blocked | expired. Mute drops proposals rather than queueing them — a stale intervention is a wrong one. Hold stops the exercise clock, and because every rule is exercise-driven, proposals cease without a second switch. The autonomy dial re-maps classes (week one: everything behaves as class C); the phase knob scales thresholds and cooldowns so week 2 Brio is more active than week 10 Brio.

05 · Control & safety model

Three gates, in series

The PRD's boundary list is enforced structurally, not rhetorically. For Brio to say anything, three independent gates must pass — and the therapist sits in front of the last one.

Gate 1 · the closed set

The engine can only emit intents from a fixed enum. There is no code path from transcript text to speech — diagnosis, advice, or free chat are not low-probability outputs; they are unrepresentable states.

Gate 2 · the validators

Deterministic checks on every candidate utterance: ≤ 2 sentences; sentence form from an allowed list (invite-with-pass, handoff, group prompt, acknowledgement, transition); banned lexicon (clinical terms, evaluative labels, child-to-child comparisons); named child only if the intent targets one; no cross-child content. Failure → pre-approved template.

Gate 3 · the human

Announce-then-act with class-based windows; mute and hold pre-empt at the audio-frame level; per-child quiet settings remove children from targeting entirely; the cue and named-move buttons make Brio an instrument, not just an actor.

The distress path is deliberately the dumbest component in the system: a conservative watchlist (self-harm, harm-from-others, acute-distress vocabulary) over every final transcript line, biased hard toward false positives. A hit changes nothing in any child's room — it pins the exact line and timestamp to a private, unmissable panel alert and logs it. No model judgment, no voiced response, no auto-escalation. Its known limits (paraphrase, mis-transcription, sarcasm) are documented in the eval report, and its vocabulary, thresholds, and the human protocol behind it are week-one work with the clinical partner.

Withheld powers, restated: Brio never controls a child's microphone (suggest-only), never moves children between rooms, never touches membership, never messages a child outside the logged, therapist-visible channel.

06 · Expression layer

How a sentence gets made

Each intent type owns a bank of hand-written, age-tuned template variants — the system is fully functional with the LLM disabled. When enabled, the LLM does exactly two bounded jobs: pick-and-vary a template so Brio doesn't sound like a metronome, and fill a group-addressed context slot from the last ~90 s of transcript ("lots of soccer fans today…"). The model receives the intent, the target (if any), tone rules, and that window — never the full session, never another child's line for a targeted utterance. Output re-enters Gate 2 before TTS. Name pronunciation comes from a phonetic field in session setup, applied at TTS time.

What the model receives, emits, and gets wrong — stated here because it is the question that matters: it receives (intent, slots, tone_rules, transcript_window); it emits one candidate sentence; it goes wrong when child speech is mis-transcribed and a confident-looking context slot is semantically off — validators catch form, not meaning. Mitigation: STT confidence gating on context slots, template fallback, and the therapist window as the last catch. This failure is reproduced deliberately in the eval fixtures.

07 · Session data

An append-only log, and everything derived from it

The event log is the source of truth: the ledger, the panel, the session-review timeline, the note drafts, and the entire eval suite are all folds over it. Hot state lives in the agent's memory; Convex persists transitions and 1 s aggregates and live-syncs every view.

Notes are generated per child from their ledger row plus only their own transcript lines, into the individualized-portion shape group documentation requires — objective counts first, quotes only from the child's own words, no clinical inference — and stay draft until the therapist edits and signs. Privacy posture, honestly: the demo runs synthetic and consenting-adult data only. A real deployment adds self-hosted LiveKit or BAA'd cloud, encrypted storage, minors' consent flows, and state-specific telehealth review — Phase 1 work, listed in the PRD's unvalidated assumptions.

08 · Evaluation

The demo cast is the test harness

Because the engine is pure and the event schema is shared, the same four scripted personas — the dominator, the silent one, the tangent-chaser, the eager helper — power the live demo (joining the room as real participants) and the headless eval suite (injecting events directly, no audio, no keys).

Unit · npm test

Engine rules in isolation: thresholds, cooldowns, ladder escalation order, lifecycle transitions, validator chain (including adversarial utterances that must fail to templates). No network, no keys, seconds to run.

Scenarios · npm run eval

Scripted sessions replayed facilitation-on vs facilitation-off. Reported per run: participation Gini across acts, silent-persona time-to-first-act (target: < 4 min on; never, off), interruptions blocked, prompts-per-child ceiling respected. Output is a written report the submission links.

Invariants · in both

Property checks over every generated log: no voiced fire without a preceding announce; nothing fires while muted or held; class C never fires from a timer; every utterance traces to an allowlisted intent; distress lines produce a flag and zero voiced responses; quiet-flagged children receive zero prompts.

What the suite proves and what it cannot: it proves the mechanism — equity math, gating, boundaries — under scripted behavior. It cannot prove children behave like scripts, that clinicians trust the panel, or that STT holds up against real child speech in home acoustics. Those are exactly the PRD's week-one discovery items; the eval report says so on its first page.

09 · Failure modes

What breaks, and what happens instead

Failure → designed degradation
FailureDesigned behavior
STT mis-hears a childthe headline AI failureContext slots gate on STT confidence; low confidence → context-free template. Airtime accounting never depended on STT. The therapist window catches what validators can't.
STT stream dropsLedger continues from audio-level events; captions pause with a panel notice; draw-outs continue (they key on airtime, not words); distress watchlist coverage gap is flagged on the panel.
LLM slow or down150 ms budget then template-only mode — Brio gets plainer, never late, never silent-by-surprise. Notes generation retries after session; the evidence log loses nothing.
TTS fails mid-utteranceCaption still renders the full line; intent marked fired(audio_failed); panel notice. Speech is enhancement; text is the guarantee.
Agent process crashesSession state re-hydrates from the Convex event log on restart; the room persists independently (LiveKit); Brio rejoins muted and waits for the therapist to unmute — never resumes acting unprompted.
A child games the petrapid-fire tapsActs rate-limit and decay; pet energy caps; taps beyond the cap still log (they're signal) but stop rewarding.
Over-prompting an anxious childthe clinical failureHard ceiling on prompts-per-child (default 3/session), ladder never skips levels, pass counts as a completed act and resets the ladder, quiet flag zeroes it — enforced by invariant tests, not intentions.
Convex write lagHot loop is in-memory and unaffected; UI staleness degrades gracefully (last snapshot + timestamp). Commands bypass Convex via the data channel, so control never lags with the database.

10 · With more time

What changes after 48 hours

First

  • Child-speech ASR evaluation — benchmark real child audio (consented corpora) across STT vendors; this is the riskiest technical assumption in the system
  • Clinical calibration — every threshold in the rule table re-derived with the therapist partner from replayed sessions
  • Distress detection beyond a watchlist — a classifier tuned with clinicians, with a measured false-negative story before any trust is placed in it

Then

  • Breakout rooms — sessions already model rooms; add room-scoped engine instances and a roving-therapist panel; adopt Realtime speech-to-speech inside breakouts where Brio genuinely converses
  • Compliance infrastructure — self-hosted LiveKit SFU, BAA'd model providers, encrypted event log, consent and retention flows
  • The between-sessions half — missions, parent loop, cohort memory (linking across weeks, therapist-triggered)
